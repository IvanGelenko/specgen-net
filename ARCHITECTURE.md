# PipingSpecPlugin (.NET) — Технологии и архитектура

> Версия 1.3.24 · AutoCAD Plant 3D 2025 (R25.0) и 2026 (R25.1) · .NET 8
> Документ описывает фактическое состояние кода в репозитории, а не план.
> Если документ и код расходятся, прав код — поправьте документ.
> Проверка точности расчёта (1.3.3) — в [ACCURACY-REPORT.md](ACCURACY-REPORT.md).

---

## 1. Назначение

Нативный плагин AutoCAD Plant 3D, который генерирует спецификацию
трубопроводов (ведомость изделий и материалов по ГОСТ 21.110, форма 1)
из активного проекта Plant 3D и выводит результат в документ Word
(`.docx`) на основе пользовательского шаблона. Рядом — служебные команды
(слои, выбор, аудит модели, синхронизация с Ведомостью трубопроводов).

Ключевые архитектурные решения:

- **Источник данных** — модель Plant 3D через `PnP*Mgd` API
  (`DataLinksManager`), а не SQLite-снимок `Piping.dcf`. Каждый чертёж
  читается как side-Database **с диска**: in-memory DLM-кэш открытого
  документа устаревает даже после `QSAVE`. Поэтому чертёж с
  несохранёнными правками генерацию не запускает — плагин просит
  сохранить его (см. §5, шаг [2]); сам он чертежи пользователя не
  сохраняет и не закрывает.
- **Кнопки на ленте** регистрируются программно, без `.cuix`.
- **Среда выполнения** — внутри процесса AutoCAD, на его UI-потоке.

## 2. Технологический стек

### Платформа и среда

- **Целевой фреймворк:** `net8.0-windows`. AutoCAD 2025 и 2026 работают
  на .NET 8 — управляемые обёртки ссылаются на `System.Runtime 8.0.0.0`.
  Любая более старая версия падает на `CS1705` при компиляции или
  `FileLoadException` при загрузке.
- **Одна DLL для 2025 и 2026.** Сборка ссылается на обёртки **2025**
  (`AcCoreMgd` 25.0.0.0, `PnP*Mgd` 16.0.58), бандл объявляет
  `SeriesMin="R25.0"`. В 2026 (25.1.0.0 / 17.0.60) .NET связывает эти
  ссылки с загруженными более новыми версиями; обратное невозможно —
  сборка против 2026 в 2025 не загрузится. Набор используемых членов API
  Autodesk в 2025 и 2026 совпадает полностью (сверено по метаданным
  обеих сборок, 1.3.19). Поэтому `AcadInstallDir` по умолчанию —
  `C:\Program Files\Autodesk\AutoCAD 2025`; тест
  `BundleSeriesMinMatchesTheReferencedAutoCadRelease` следит за парой
  «SeriesMin ↔ AcadInstallDir».
- **Платформа:** только x64.
- **Тип сборки:** библиотека классов (DLL), загружается через
  AutoLoader-бандл (`%APPDATA%\Autodesk\ApplicationPlugins`) или `NETLOAD`.
- **UI-стек:** WPF (`UseWPF`) + Windows Forms (`UseWindowsForms`) —
  WPF для окон, WinForms для системных диалогов (`SaveFileDialog`,
  `OpenFileDialog`, `MessageBox`).
- **Язык:** C# (`LangVersion=latest`), `Nullable` отключён.

### Внешние зависимости

- **DocumentFormat.OpenXml 2.20.0** (NuGet) — запись `.docx`
  (спецификация, отчёт аудита) и чтение `.xlsx` (ВТ). Намеренно ветка
  2.x: 3.x убрала legacy-API. `CopyLocalLockFileAssemblies=true` кладёт
  DLL рядом с плагином, установщик ставит её в бандл.
- **System.Text.Json** (BCL) — настройки, ответ GitHub API, JSON аудита.

## 4. Точки входа

| Команда | Класс | Лента | Что делает |
|---|---|---|---|
| `WRITESPECPROJ` | `WriteSpecCommand.RunProject` | «Весь проект» | спецификация по всему проекту |
| `WRITESPECDWG` | `WriteSpecCommand.RunDrawing` | «Текущий чертёж» | спецификация по активному чертежу (читает только его) |
| `WRITESPEC` | `WriteSpecCommand.Run` | — | область берётся из окна выбора (по умолчанию — последняя использованная) |
| `SYNCVT` | `SyncVtCommand` | «Синхронизация ВТ» | ВТ (.xlsx) → свойства `P3dLineGroup` |
| `INSULSPECPROJ` | `InsulationCommand.RunProject` | «Изоляция → Весь проект» | данные для расчёта изоляции по всему проекту (§10c) |
| `INSULSPECDWG` | `InsulationCommand.RunDrawing` | «Изоляция → Текущий чертёж» | то же по активному чертежу (читает только его) |
| `INSULSPEC` | `InsulationCommand.Run` | — | область выбирается в окне |
| `INSULHELP` | `InsulationCommand.Help` | «Изоляция → Методика» | окно «Методика расчёта изоляции» |
| `PSAUDIT` / `PSAUDITJSON` | `AuditCommand` | «Аудит» / — | проверка стенок, соединений, коллизий |
| `MOVEBYTAG` | `MoveToLayerCommand` | «Разнести по слоям» | арматура/оборудование на слои по Tag |
| `SELECTBYSTATUS` / `SELECTBYLINE` / `SELECTBYLAYER` | Select*Command | «Выбор», «Слои» | выделение по свойству |
| `PSCOLORBYLAYER` | `ColorByLayerCommand` | «Цвет по слою» | цвет объектов по слою |
| `SPECABOUT` | `AboutCommand` | «О программе» | версия, обновления |
| `CONNECTALL` / `CONNECTALLDIAG` | `ConnectAdjacentCommand` | скрыты | незавершённая функция |

Команды спецификации и `SYNCVT` помечены `[CommandFlags.Session]`
(работа на уровне сессии — нужно для side-чтения чертежей и модальных окон).

Регистрация в `AssemblyInfo.cs`: `[assembly: CommandClass(...)]` для
каждого класса с командами и `[assembly: ExtensionApplication(typeof(PluginBootstrap))]`.
`GenerateAssemblyInfo=false`; версия сборки генерируется из `$(Version)`
таргетом `GenerateVersionInfo` в csproj.

### Лента (`PluginBootstrap`)

`Initialize()` вызывается один раз при загрузке сборки:
1. Строит вкладку **«Спецификация»** (панели «Спецификация», «Изоляция», «Слои»,
   «Ведомость трубопроводов», «Выбор», «Проверка модели», «Справка»).
   Если лента ещё не создана — ждёт `ComponentManager.ItemInitialized`
   и отписывается, как только вкладка появилась.
2. Подписывается на `RibbonPaletteSet.WorkspaceLoaded` (через
   `RibbonServices.RibbonPaletteSetCreated`, если палитры ещё нет):
   AutoCAD перестраивает ленту из CUIx при смене рабочего пространства /
   `CUILOAD`, и вкладка, созданная кодом, исчезает — обработчик создаёт
   её заново. Повторное создание идемпотентно (поиск по `Id`).
3. Запускает фоновую проверку обновлений (§10a).

Каждый шаг в своём `try/catch`: исключение из `Initialize` сорвало бы
загрузку плагина целиком. Иконки рисуются кодом (`UI/CommandIcons`);
кнопка вызывает команду через `SendStringToExecute`.

## 5. Конвейер генерации спецификации

`WriteSpecCommand.RunCore` — одно нажатие кнопки:

```
[1] Проверки         → открыт ли проект Plant 3D; для WRITESPECDWG — открыт ли чертёж
        ↓
[2] Сохранённость    → открытые чертежи из области сканирования с несохранёнными
                       правками → сообщение «Сохраните чертёж … и повторите», стоп.
                       Плагин сам ничего не сохраняет и не закрывает.
        ↓
[3] Сканирование     → WRITESPECDWG: только активный чертёж (ProjectScanner.ScanSingleDrawing);
     (ProgressWindow)   иначе все DWG поддерева "Plant 3D Models" (ProjectScanner.ScanProject).
                        Каждый чертёж — side-Database с диска → PartReader.
                        Идентификаторы деталей переводятся в единое для прохода
                        пространство (DrawingPartIds, отрицательные id).
                        Любой пропущенный чертёж (нет файла, ошибка чтения,
                        PnpReconnectFailed, WorkingDbSwapFailed) — стоп.
        ↓ ScanResult { records, activeDwgRecords, ownedPnPIds, topology, unreadParts }
[4] Спутники арматуры → ValveCompanionFinder.Discover (на всех записях скана)
        ↓
[5] Picker           → ProjectFacts (без owned-деталей) питают чекбоксы;
     (SpecPickerWindow)  пользователь выбирает статусы / категории / линии и опции
        ↓ SpecPickerResult
[6] Фильтр области   → scope=dwg сужает records по SourceDwgPath (НЕ по PnPID)
        ↓
[7] Агрегация        → SpecRowBuilder.Build: фильтры, сворачивание изгибов
                       (PipeBendFolder — внутри Build, на отфильтрованных записях),
                       бакеты → List<SpecRow> + ReviewItems
                     → ReviewSection.BuildRows (непрочитанные детали + сомнения)
        ↓
[8] Запись           → AskOutputPath → SpecTemplateWriter.Write → .docx
                       (последним — раздел «Позиции, требующие проверки»; если
                       основная спецификация пуста, документ состоит только из него)
        ↓
[9] Сохранение prefs → PluginSettings.Save (только после успешной записи)
                       → открыть в Word (если включено)
```

Каждый шаг пишется в `%APPDATA%\PipingSpecPlugin\last-run.log`
(`RunLogger`): в командную строку — короткие сообщения, в файл — полный
трейс (дампы изгибов с длиной и массой, труб по линиям, `DropReasons`).

### Непрочитанные и сомнительные детали

Деталь, которую `PartReader` не смог прочитать
(`PartReadResult.SkippedRowDetails`), **не останавливает** генерацию —
она попадает в раздел «Позиции, требующие проверки» (`Spec/ReviewSection.cs`)
с PnPID, чертежом и причиной. Генерацию останавливают только сбои всего
чтения чертежа (`ReviewSection.ReadStopsGeneration`):
`PnpReconnectFailed`, `WorkingDbSwapFailed`, а также файл не найден / не открылся.

`SpecRowBuilder` вместо исключений собирает `ReviewItems`: неизвестная
единица длины (труба исключается), некорректное количество / нет
количества у `BoltSet` (исключается), труба нулевой длины (исключается),
неизвестная единица массы/погонной массы и отсутствие массы (деталь
остаётся, масса не учтена), разная масса в строке, несколько групп линии
/ группа линии не прочитана (`PartRecord.ReadWarnings`), пустое
наименование, деталь без категории, гиб без совместимой трубы,
нераспределённые метры гибов. Штатные исключения фильтрами (статус /
категория / линия, штуцера, спутники арматуры, швы/прокладки/болты
штуцеров оборудования) сомнениями не считаются. Одна деталь = один пункт
на проблему (повторы по «причина + PnPID + чертёж» убираются);
одинаковые проблемы группируются в одну строку по «причина +
наименование». Раздел пишется последним, без номеров позиций,
количество/масса — только если известны; в нумерацию позиций не входит.

## 6. Слой доступа к данным (`PartReader`)

### Откуда берутся данные

- `DataLinksManager.GetManager(db)` → `SelectAcPpRowIds(db)` даёт rowId
  каждого `EngineeringItem`; дополнительно ModelSpace проверяется на
  сущности `AcPp*` (`FindAcPpRowId`).
- `GetAllProperties(rowId, true)` возвращает мешок свойств; он один раз
  приводится к словарю и мапится в `PartRecord` (`PartPropertyReader`).
  У изгиба (`PipeBend`) длина — дуга `CutLength`.
- Каждый rowId читается один раз → одна `PartRecord` на деталь.

### Ключевые приёмы и подводные камни

- **`WorkingDatabase` swap.** `GetRelatedRowIds` на side-DB резолвит
  данные через нативный слой, привязанный к
  `HostApplicationServices.WorkingDatabase`. На время чтения рабочая БД
  переключается на читаемую, иначе `RowNotInThisDatabase`. Сбой
  переключения (`WorkingDbSwapFailed`) останавливает генерацию.
- **Принудительный сброс кэша.** Перед запросом — `AcceptChanges` /
  `AuditDrawing` / `ReloadLinkMap` / `AuditLinks` / `RefreshLinkMap` на
  DLM чертежа и проекта, затем `PnpDbFreshness.Flush` (Disconnect/Connect
  `PnPDatabase` с гарантированным повторным подключением; не
  переподключилась → `PnpReconnectFailed`). Последовательность
  эмпирическая, каждый сбой пишется в лог.
- **Живой тег линии (`ResolveLiveLineTag`).** Свойство `LineNumberTag`
  детали устаревает при переименовании линии. Реальный тег читается
  через `P3dLineGroupPartRelationship` → строку `P3dLineGroup` —
  **только через DLM чертежа**: rowId детали живёт в пространстве id
  чертежа, и запрос к project-DLM с ним мог вернуть чужую линию. Не
  нашлось — берётся собственное свойство детали. Несколько групп линии —
  берётся первая, деталь помечается для раздела проверки.
- **Топология (`BuildTopology`).** `ConnectionManager.GetConnections` для
  каждой сущности даёт прямые рёбра «деталь ↔ деталь». **Не**
  `ConnectionIterator` (транзитивное замыкание → ложные спутники арматуры).
- **Оборудование и штуцера.** `Runtime.IsPnP3dEquipment` /
  `IsPnP3dNozzleSubPart` / `IsPnP3dConnector` и связь AssetOwnership
  помечают детали, принадлежащие оборудованию. Закупочные категории
  (трубы, детали, арматура, фланцы) owned **никогда** не помечаются
  (`CategoryClassifier.IsProcurementCategory`).
- **Единицы чертежа.** `Database.Insunits` → `PartRecord.DrawingMmPerUnit`
  (координаты Position/COG — в единицах чертежа); без INSUNITS считается мм.

## 7. Доменная логика

### `CategoryClassifier`

`Normalize` — категория для фильтров и picker'а (опоры по
`TYPE=SUPPORT`/классу/описанию, пустая категория → по классу:
`P3dConnector`, `Equipment`, …). `SpecSection` — раздел вывода после
фильтров: синонимы (`Support`/`Supports`, `Instrument`/`Instruments`,
`PipeSpecialty`/`Specialty`/`PipeSpecialties`) сводятся к одному разделу;
изгиб при выключенном «Учитывать изгибы как трубу» — «Детали
трубопроводов» (шт.), при включённом сирота с длиной — «Трубы» (м), без
длины — «Детали» (шт.).

### `PipeBendFolder` — сворачивание изгибов

Вызывается из `SpecRowBuilder.Build` (опция включена) на записях,
прошедших фильтры пользователя, плюс все коннекторы для обхода графа.
Цель — та же закупочная позиция, что и изгиб (`SameItem`: чертёж, линия,
материал, спецификация, стенка, schedule, класс давления, Ду и его
единица) с положительной длиной. Поиск: прямой сосед → через один
коннектор → обход в ширину через коннекторы и изгибы той же позиции
(цепочки «гиб–шов–гиб»). Нет подходящей трубы → изгиб-сирота
(`OrphanBends`), остаётся своей строкой. Метры, «застрявшие» на
отфильтрованной трубе, переносятся на трубу-сиблинг с той же закупочной
идентичностью (`FallbackKey`); иначе — в раздел проверки с длиной.

`BendNameNormalizer`: в наименовании изгиба длина округляется до 1 знака,
Д1/Д2 сортируются — один и тот же изгиб не дробится на строки.

### `ValveCompanionFinder` — спутники арматуры

Обходит граф `Арматура → Коннектор → Фланец`, находит ответные фланцы, а
для каждого — ближайшую прокладку и комплект болтов того же чертежа,
Ду, спецификации и линии в радиусе 100 мм (переводится в единицы
чертежа по INSUNITS; без INSUNITS — мм). Без координат — только
однозначный кандидат по тому же ключу. Трубы/детали/арматура/оборудование
в исключения не попадают. Исключаются только при включённой опции.

### `SpecRowBuilder` — агрегация

Конвейер фильтров (каждый отсев считается в `DropReasons`):

1. свёрнутые изгибы → `pipe-bend-folded`
2. статус
3. детали, принадлежащие оборудованию
4. спутники арматуры (опционально)
5. категория `Equipment` / коннекторы (флаги `ExcludeEquipment` /
   `ExcludeConnectors`; picker передаёт `false` — их заменяют чипы категорий)
6. штуцера оборудования — **всегда**
7. пустая категория → раздел проверки
8. выбранные категории
9. выбранные линии
10. дедуп по `PnPID`
11. труба нулевой длины / неизвестная единица длины, некорректное
    количество крепежа → раздел проверки

Затем агрегация в бакеты по `BucketKey`: раздел, наименование, Ду
(округлён до 0.001), единица Ду, материал, тип/марка, код, поставщик,
линия (при группировке), класс давления, исполнение уплотнения,
стандарт, стенка, schedule (и `PnPID` при «Не группировать»).

- **Трубы** суммируют длину в `decimal` с переводом единиц в метры,
  плюс метры свёрнутых изгибов. Сумма приводится к 1 мкм (шум double) и
  округляется **вверх** до 0.1 м; примечание «с учетом 10% запаса: X м»
  считается от выведенного количества и тоже округляется вверх.
- **Масса 1 ед.**: для труб — кг/м (`LinearWeight` с учётом единицы, иначе
  `Weight / длина`); для штучных — `Weight` / количество в комплекте.
  Изгиб в штуках без своей массы получает `CutLength × LinearWeight`
  (`BendMassFromLinearWeight`), если оба значения есть в его записи.
  Значение — средневзвешенное по бакету; разброс > 5 % → раздел проверки.
- **Крепёж** учитывает `NumberInSet` (8 болтов = 8 шт.); `BoltSet` без
  количества не считается «1 шт.», а уходит в раздел проверки.
- **«Тип, марка…»**: у арматуры и оборудования с тегом — список тегов
  (естественная сортировка), иначе `DesignStd` / `CompatibleStandard`.
- **Сортировка** — полный порядок: линия (естественная сортировка) →
  порядок разделов `CategoryOrder` → Ду → наименование (естественная
  сортировка: «108х4» раньше «108х10») → остальные поля.

### `SpecConstants`

Сентинелы (`__NULL__`, `__NULL_STATUS__`, `__NO_LINE__`), русские метки
категорий, порядок разделов, ключевые слова, заголовок секции шаблона
`«Изделия и материалы»` — он должен совпадать с текстом шаблона `.docx`
(по нему writer находит таблицу). Заголовок раздела проверки writer
пишет сам, его можно менять.

## 8. Вывод в Word (`SpecTemplateWriter`)

Запись поверх **пользовательского шаблона**: шаблон копируется во
временный файл рядом с выходным, заполняется и атомарно переносится на
место выходного (`File.Move`); шаблон не меняется. Алгоритм:

1. найти таблицу с одноячеечной строкой-заголовком «Изделия и материалы»
   (допускается номер раздела перед текстом);
2. строки шаблона под заголовком (до следующей одноячеечной строки) —
   **резерв**: все должны иметь 9 ячеек, иначе вывод останавливается;
3. трафарет новых строк — **последняя строка резерва** (рамки, свойства
   строки, ширины), стиль текста по колонкам — **первая строка резерва**
   (выравнивание, шрифт с метки абзаца). Только шаблон без резерва
   берёт любую 9-ячеечную строку таблицы (обычно строку заголовков
   колонок). У трафарета снимаются вертикальный текст, объединения,
   фиксированная высота и флаг повтора заголовка (`w:tblHeader`);
4. для каждой группы `(линия → раздел)` — подзаголовок (9 ячеек,
   `hMerge` restart/continue, жирный), затем строки данных с номерами
   позиций; сначала заполняются строки резерва, потом добавляются копии
   трафарета;
5. если есть позиции для проверки — подзаголовок «Позиции, требующие
   проверки» и строки без номера позиции;
6. неиспользованные строки резерва удаляются.

Колонки (ГОСТ 21.110, форма 1): `Поз. | Наименование и техническая
характеристика | Тип, марка, обозначение документа | Код продукции |
Поставщик | Ед. изм. | Кол. | Масса 1 ед., кг | Примечание`. Числа — с
десятичной точкой; нулевая масса (и неизвестное количество в разделе
проверки) — пустая ячейка.

Свойства элементов вставляются типизированными сеттерами OpenXml
(`TableCellProperties.HorizontalMerge`, `RunProperties.Bold`), чтобы
соблюдался порядок схемы — документ проходит `OpenXmlValidator`. Весь
текст проходит `XmlText`: управляющие символы, недопустимые в XML
(они роняли `Document.Save()` целиком), удаляются, табуляция и переводы
строк в ячейке становятся пробелом. Штамп и колонтитулы шаблона плагин
не трогает.

## 10. Настройки (`PluginSettings`)

`%APPDATA%\PipingSpecPlugin\settings.json`.

- Схема версионируется (`CurrentSchemaVersion = 8`; v8 — настройки INSULSPEC) с forward-only
  миграциями (`Upgrade`). Неизвестные поля игнорируются, отсутствующие
  берут значения по умолчанию.
- Повреждённый файл не блокирует плагин: загружаются умолчания с флагом
  `LoadFailed`; WRITESPEC при сохранении копирует старый файл в
  `settings.json.unreadable`, SYNCVT такие умолчания не сохраняет вовсе.
- Запись атомарная: уникальный временный файл + `File.Move`.

Сохраняются: путь шаблона, последняя папка вывода, область
(`proj`/`dwg`), группировка по линии, опции, выбранные и «известные»
статусы/категории/линии, путь последней ВТ. Известный, но не выбранный
ключ — снятый пользователем; неизвестный — новый, отмечается по
умолчанию. Окно выбора показывает чипы одной области; при области
«чертёж» ключи, которые не были показаны, сохраняют прежнее состояние
(`PickerSelectionMemory`).

## 10a. Автообновление (`Update/`)

- **Триггер** — `PluginBootstrap.Initialize`, фоновая задача (не
  блокирует загрузку), при каждом запуске AutoCAD, если
  `PluginSettings.CheckForUpdates` (по умолчанию вкл.).
- **`UpdateChecker`** — чистая логика: разбор JSON релиза GitHub,
  сравнение версий покомпонентно числами (`1.3.10 > 1.3.9`, префикс `v`,
  суффикс `-rc` отбрасывается), digest `sha256:` и размер ассета.
- **`UpdateService`** — `HttpClient` к
  `repos/IvanGelenko/specgen-net/releases/latest` (черновики и
  pre-release этот endpoint не отдаёт); любой сбой (офлайн, rate limit,
  битый ответ) → тихо «нет обновлений». Установщик скачивается в
  `%TEMP%` во временный `.part`, проверяется размер и SHA-256 и только
  потом запускается.
- **`UpdateWindow`** — «текущая → новая» + заметки релиза; «Обновить»
  можно повторить после сбоя. AutoCAD держит DLL всю сессию, поэтому
  установка завершается **после закрытия AutoCAD**.
- **Версия** — `AssemblyVersion` (из файла `VERSION` через `build.cmd`).
  Релиз должен иметь тег `vX.Y.Z` и ассет `PipingSpecPlugin-Setup.exe`.

## 10b. Синхронизация ВТ (`SYNCVT`)

Единственный путь, где плагин **пишет** в базу проекта.

- `VtReader` читает первый лист `.xlsx` (OpenXml): колонки по тексту
  заголовков (строка 1, группы — строка 2), строки-заголовки разделов
  (широкий merge или одна непустая ячейка) пропускаются; ключ строки —
  колонка «n/n».
- `LineSyncService.ReadAllLines` читает `P3dLineGroup` через project-DLM
  (дубли rowId отбрасываются); `BuildPlan` сопоставляет «n/n» ↔ свойство
  `ID` линии (trim, без учёта регистра). Повторяющийся «n/n» в ВТ —
  все такие строки пропускаются; повторяющийся `ID` в проекте — меняются
  все совпавшие линии (с предупреждением). **Пустая ячейка ВТ никогда не
  стирает значение в проекте.** Числовые поля сравниваются по значению
  («1,6» = «1.60»), коды и идентификаторы — как текст. Из «Обозначения»
  декодируются Size2, код среды, материал, давление, фланцы, изоляция,
  обогрев (`LineDesignationParser`); первая строка обозначения пишется
  в `Tag` без текста в скобках (`LineDesignationParser.TagOf`: «150-…-HN
  (Врезка 2; 5)» → «150-…-HN»), трёхзначный номер — в `Номер`.
- `SyncVtWindow` показывает «внутреннюю ведомость» и план, запись — только
  после подтверждения; `Apply` выполняет все `SetProperties` в одной
  транзакции `PnPDatabase` (`SyncTransaction`: сбой → откат, ошибки
  показываются). Поиск/удаление «линий-сирот» (`FindOrphanLines` /
  `DeleteOrphanLines`) в коде есть, но нигде не вызывается.

## 10c. Данные для расчёта изоляции (`INSULSPEC`)

Исходные данные для программы расчёта тепловой изоляции: по каждой
линии — трубы с изоляцией (м) и фитинги — отводы, изгибы, тройники (шт.).
Панель «Изоляция»: «Весь проект» (`INSULSPECPROJ`), «Текущий чертёж»
(`INSULSPECDWG` — читает только активный чертёж), «Методика» (`INSULHELP`,
также кнопка в окне; текст держать в синхроне с `InsulationTakeoff`).
`INSULSPEC` — командная строка, область выбирается в окне. Лог —
`last-run-insulspec.log`.

- **Поток:** проверка сохранённости → `ProjectScanner.ScanProject` /
  `ScanSingleDrawing` → изолированные детали классов Pipe / PipeBend /
  Elbow / Tee без принадлежащих оборудованию → `InsulationPickerWindow`
  (статусы, линии) → `InsulationTakeoff.Prepare` → **`SpecRowBuilder`**
  (`GroupByLine`, `IncludePipeBendsAsPipe = false`) → `InsulationListWriter`.
- **Подсчёт — как в спецификации** (по прямой просьбе пользователя):
  те же фильтры, наименования («Полное описание (размер)»), группировка
  позиций и округление (трубы — метры вверх до 0.1 м; запас 10 % не
  выводится; длина изгиба в наименовании — до 0.1 мм через
  `BendNameNormalizer`). Замечания построителя о массе отбрасываются
  (`WithoutMassNotes`) — масса в этом выводе не участвует.
- **Изоляция:** деталь учитывается, только если её **собственная**
  `InsulationThickness` > 0 (там Plant 3D рисует изоляцию); свойства линии
  не используются — неизолированный участок изолированной линии не
  попадает (temp.dwg: 2 м трубы, изоляция на изгибе и 1 м → 1.2 м + 1 изгиб).
- **Изгибы** (`BendDescription`): из «ИЗГИБ ТРУБЫ: Р = 90, У = 90 град,
  Д1 = 100, Д2 = 100, ДЛИНА ТРУБЫ = 341.3717, Труба 25х4 …» — копия детали
  с наименованием «ИЗГИБ ТРУБЫ 25х4, Р = 90, У = 90 град, ДЛИНА = 141.3717»
  (дуга = ДЛИНА ТРУБЫ − Д1 − Д2; без длины — R·θ) и запись-хвост трубы
  длиной Д1 + Д2: копия трубы той же линии с тем же описанием (сравнение
  без учёта регистра, «х/x/×» и пробелов, чтобы попасть в её строку
  спецификации), иначе — труба с описанием из изгиба. Нет Р или У —
  изгиб как есть + раздел проверки.
- **Вывод** (`InsulationListWriter`, без шаблона): заголовок, «Линия …»,
  под ней нумерованный список «Наименование — количество ед.», в конце
  «Позиции, требующие проверки». Запись через
  `SpecTemplateWriter.WriteDocument` (пустой A4 → заполнение → замена).
- **Настройки:** `InsulationScope`, `InsulationLines` /
  `InsulationStatuses` и их `Known*` (схема v8; ключи прежних вариантов
  v6–v7 — материалы, типы изоляции — игнорируются).

## 10d. Аудит модели (`PSAUDIT` / `PSAUDITJSON`)

Проверка выбранных линий текущего чертежа; модель не изменяется.
`PSAUDIT` — окно `AuditWindow`: линии, проверки, реестр замечаний,
«Выделить и закрыть», отчёт .docx по встроенному
`AuditReportTemplate.docx` (`AuditDocxReport`). `PSAUDITJSON` — все
проверки по всем деталям, JSON (`AuditReport`) для скриптов и
`tools/AuditSmoke`. Логи — `last-run-psaudit.log` / `last-run-psauditjson.log`.

- **Данные:** `AuditLineCatalog` читает **сохранённую копию** (`PartReader`,
  как SELECTBYLINE) — номер линии и свойства каждого элемента по handle;
  `DrawingAuditReader` открывает живой чертёж (порты, соединения,
  геометрия), свойства берёт из каталога, при отсутствии — из живого DLM.
  Несохранённые изменения: `PSAUDIT` спрашивает о сохранении
  (`DrawingSaveGuard`), `PSAUDITJSON` останавливается. Непрочитанные строки
  аудит не останавливают — «Не проверено»; останавливает только сбой всего
  чтения (`ReviewSection.ReadStopsGeneration`, как в спецификации).
- **Правила** — реестр `AuditRules.All` (окно и отчёты строятся по нему):
  - *толщины стенок* — трубы / отводы / изгибы одной линии с одинаковым Ду,
    допуск 0.01 мм; замечание — на каждую пару соединённых (напрямую или через
    объект соединения) деталей, где стенка меняется (`WallChanges`, 1.3.31,
    просьба пользователя вместо общего списка); участок другой стенки, не
    граничащий с трубой / отводом другой стенки, — одно замечание против
    основной стенки линии (большинство, при равенстве — толще); тройник / переход (`Tee` / `Reducer`) — стенка конца не
    тоньше трубы, приваренной к нему (напрямую или через объект соединения),
    конец — с Ду трубы: S1 из строки детали, остальные — строки `Port` через
    связь `PartPort` (`DrawingAuditReader.ReadEnds`, `AuditPart.Ends`; у
    перехода 159x8-89x6 S1 = 8 мм, S2 = 6 мм). Соединения поэтому читаются и
    для этой проверки. Толщина — в единице **каталога детали** (`LengthUnit`,
    пусто = мм, общая таблица `Spec/LengthUnits` — та же, что у длин в
    спецификации), не в единицах чертежа (INSUNITS);
  - *соединения* — свободные порты и разрывы линии: компоненты связности
    деталей с портами; путь идёт через соединители без линии или той же
    линии и через непрочитанные трубы / отводы линии (известные рёбра к ним
    физические). «Не проверено» вместо «Проверить» — только если участки
    могут соединяться через неизвестное: деталь с непрочитанным номером
    линии (`LineUnknown`), деталь линии с непрочитанными портами (опорой она
    может быть — мостом не считается) или ребро между двумя элементами с
    непрочитанными соединениями (только такие рёбра могут отсутствовать в
    данных; union-find в `ConnectivityRule`);
  - *материал деталей линии* (`MaterialRule`, 1.3.31) — трубы и фасонные
    детали одной линии одного материала (`Material`, пустой — `MaterialCode`;
    `Normalize`: «Сталь 20» = «20», регистр, пробелы, латинские двойники в
    русской марке). Не сравниваются арматура / приборы / опоры / соединения
    (`NotCompared` по классу: в audit-model.dwg у задвижек «хладостойкая
    сталь», у опор ВСт3пс). Замечание называет детали, отличные от
    материала большинства (без большинства — все); пустой материал —
    «Не проверено». Детали без номера линии не проверяются. Прогон
    audit-model.dwg: 150-P22002/2-LS025C-HN — три трубы из стали 20 при 09Г2С;
  - *длина болтов и шпилек* (`BoltLengthRule`, 1.3.31) — комплект болтов
    объекта соединения не короче пакета + гайки 0,8·d (шпилька — две, болт —
    одна; тип по описанию / стандарту, ОСТ 26-2040 — шпилька; неизвестный —
    болт). Пакет: зазор прокладки (расстояние между портами соединения, по
    модели, `DrawingMmPerUnit` = INSUNITS, иначе единицы проекта Plant) +
    толщины фланцев (`FlangeThickness` порта, DLM: S1 — строка детали,
    остальные — `PartPort`), у межфланцевой арматуры (WF) и поворотной
    заглушки (`BlindDisk`) — ещё корпус, второй зазор и дальний фланец.
    Plant 3D сам прокладку не учитывает (статьи поддержки Autodesk).
    Комплект — подобъект `BoltSetSubPart`, его строка DLM —
    `FindAcPpRowId(MakeAcPpObjectId(id, i))` (Length, BoltSize, LengthUnit),
    без строки — `BoltSetSubPart.Length`. Связи портов — `Connection.Port1/2`
    (`AuditPart.Links`, могут быть записаны с одной стороны — `LinksOf`).
    Нет толщины у одной стороны (арматура в каталоге часто без неё) — берётся
    толщина другого фланца пакета, нехватка — «Проверить»; так же при
    комплектах по обе стороны заглушки (Plant ставит два, шпилька физически
    одна). LUG — «Не проверено». **`SpecPort` / `PartSizeProperties.PropValue`
    не использовать:** имя, которого у порта нет, — AccessViolation в нативном
    коде, AutoCAD падает (accoreconsole 2026, audit-model.dwg); без проекта
    `PropNames` к тому же пуст. Прогон 1.3.31 на audit-model.dwg: 35
    соединений, 23 в норме, 8 «Проверить» (заглушки DN150 PN25: M24×120 при
    пакете 83–87 мм), 2 «Не проверено» — `artifacts/audit/bolts-report.json`;
  - *коллизии* — explode в `Solid3d`, X-sweep, `CheckInterference` + объём
    пересечения; **допуск** (1.3.31, поле в окне, `AuditOptions.CollisionToleranceMm`,
    хранится в `settings.json` → `AuditCollisionToleranceMm`, им же пользуется
    PSAUDITJSON): пересечения не глубже допуска не учитываются
    (`CollisionsWithinTolerance`). Глубина = наименьшая сторона габарита
    области пересечения (`OverlapDepth`) — не меньше истинной, допуск не
    скроет более глубокое; в сообщении «Глубина ≈ N мм». Изоляция
    проверяется, если тела в пределах допуска. Прогон audit-model.dwg: 0,7 /
    5 / 5,5 / 45 мм, при допуске 6 мм осталось одно (45 мм);
    **конструкции между собой** (1.3.31, флажок, `StructureCollisions`,
    `settings.json` → `AuditStructureCollisions`, по умолчанию вкл.):
    «конструкция» = не деталь Plant (`Shape.IsStructure`: металлоконструкции,
    3D-тела, блоки, объекты внешних ссылок); пара двух конструкций
    проверяется и при выборе линий, замечание `BetweenStructures` проходит
    фильтр `CollisionRule`. Части одной вставки / ссылки между собой — как и
    раньше, нет. Узел металлоконструкции (`StructureJointPolicy`: конец оси
    элемента ACPPSTRUCTURE*, `Curve.StartPoint/EndPoint`, внутри области
    пересечения ±1 мм) не коллизия, счётчик `StructureJointsIgnored`.
    В audit-model.dwg металлоконструкций Plant нет — правило узла проверено
    только тестами; изоляция — отдельно (голый клон с `InsulationDiameter = 0`);
    внешние ссылки и вставки обходятся по определениям блоков, ключ
    `вставка/…/handle` (у детали ссылки — описание и линия из DLM её
    чертежа; в столбце «Линия» с пометкой «(ссылка имя)», ключ линии без
    пометки). Не считаются: опора ↔ её деталь
    (`SupportContactPolicy`), детали, соединённые через объект соединения
    (шов, фланцевое соединение, врезка), и сам объект ↔ соединяемая им
    деталь (`ConnectedJointPolicy`; найденные такие пересечения считаются в
    `ConnectedJointsIgnored`, соединения читаются и при выключенной проверке
    соединений), только изоляция на одной линии (`InsulationJointPolicy`),
    части одной вставки блока между собой.
    2D-объекты (`IsFlat`: собственные кривые AutoCAD — `IsPlainCurve`,
    тексты, размеры, штриховки, выноски, изображения, подложки, 2D SOLID)
    объёма не имеют и пропускаются. Изо-символы Plant 3D
    (`AcPpDb3dIsoSymbol` и наследники: IsoSphereSymbol, IsoArrowSymbol,
    IsoStartPointSymbol, IsoRefDim — по цепочке RX-классов, `IsIsoSymbol`)
    — наследники `Part`, но аннотации изометрии: исключены из аудита целиком
    (1.3.31). **Балки / колонны металлоконструкций
    Plant 3D** — `ImpCurve` (ACPPSTRUCTUREBEAM, наследник кривой): не плоские,
    explode даёт Solid3d (раньше пропускались как 2D). `SubDMesh` —
    `ConvertToSolid`; у копии Solid3d отключается `RecordHistory` (тело с
    историей давало eWasOpenForWrite в каждой булевой операции). У MINSERT
    проверяется только первая копия — с замечанием «Не проверено».
- **Порядок замечаний** (1.3.31, `AuditRules.Order`, его возвращает `Run` —
  одинаково в окне, JSON и .docx): группы коллизии → болты → стенки →
  материал → соединения → чтение данных; в группе нарушение →
  «Проверить» → «Не проверено», затем `AuditIssue.Magnitude` по убыванию
  (глубина коллизии, нехватка длины болта, разброс / недостача стенки в мм,
  число отличающихся деталей, число участков линии), затем линия и текст.
  В окне таблица сгруппирована по `AuditIssue.Group` (заголовок «проверка —
  число»), столбца «Проверка» нет. Параметры (линии, проверки, допуск) —
  `Expander`, после проверки сворачивается, в заголовке — с чем запускали.
  `tools/AuditPreview` показывает окно за экраном и ждёт простоя диспетчера
  (иначе колонки рендерились минимальной ширины); `AUDIT_PREVIEW_REPORT` —
  JSON-отчёт, из которого берутся коллизии.
- **Замечания чтения** скрываются, только если все их элементы заведомо на
  невыбранных линиях; элемент с неизвестной линией показывается всегда.
- **Список линий** — по элементам чертежа (число = элементов, как в итоге
  аудита, а не строк данных); линия, все строки которой ушли в элементы
  других линий (прокладки, крепёж), не показывается.
- **Показ в модели** (`Commands/AuditModelView`, кнопка «Показать в модели»
  и двойной щелчок по строке): `Editor.StartUserInteraction(window)` прячет
  модальное окно; вид наводится на `AuditIssue.Bounds` (у коллизии —
  пересечение рамок пары, есть и в JSON) или на рамки элементов; элементы
  подсвечиваются — вложенные во вставку / внешнюю ссылку через
  `FullSubentityPath` (ключ `вставка/…/handle` разворачивается по базам
  определений, у ссылки — её собственная база); Enter — снять подсветку и
  вернуться к тем же результатам. «Выделить и закрыть» — implied selection
  по `SelectableKeys` (для элемента ссылки — её вставка).
- `tools/AuditPreview` рисует окно в PNG без AutoCAD (`… parts.json out.png
  "" run` — с результатами); окно поэтому не ссылается на AutoCAD-классы.
- `tools/AuditSmoke` — прогон без интерфейса: accoreconsole AutoCAD 2026 на
  **копии** чертежа, `_NETLOAD` PnP3dObjectsMgd + AuditSmoke; команды
  AUDITSMOKE (живые данные, `AUDIT_SMOKE_LINE` — одна линия), AUDITCATALOG
  (через DLL плагина `AUDIT_PLUGIN_PATH`, как PSAUDIT), AUDITSHAPES (что
  получается из каждого объекта), AUDITBOOLTEST. При SECURELOAD=1 папку
  сборки надо добавить в TRUSTEDPATHS в начале скрипта и вернуть в конце.

## 11. Слой UI

Все окна — WPF, владелец задаётся через
`WindowInteropHelper.Owner = AcadApp.MainWindow.Handle`, показ —
`ShowDialog()` (прогресс — `Show()`).

- **`SpecPickerWindow`** — выбор фильтров и опций. Питается
  `ProjectFacts` (две копии: весь проект и активный чертёж).
  При запуске кнопкой область фиксирована (`forcedScope`).
  Пустая область → кнопка «Сгенерировать» недоступна с объяснением.
- **`ProgressWindow`** — прогресс сканирования. Отмена (кнопка или
  закрытие окна) проверяется между чертежами: текущий чертёж дочитывается,
  затем команда завершается без picker'а.
- **`SyncVtWindow`**, **`UpdateWindow`**, **`AuditWindow`**, **`AboutWindow`**.

> AutoCAD 2025+ `Application.ShowModalWindow` принимает только `Uri`,
> не сконструированный `Window` — поэтому `WindowInteropHelper` + `ShowDialog`.

## 12. Сборка, загрузка, эксплуатация

### Сборка

```powershell
.\build.cmd      # VERSION → dotnet build (bin\Release-vX.Y.Z) → bundle_staged → Inno Setup
                 # → dist_installer\PipingSpecPlugin-Setup.exe
dotnet test test\PipingSpecPlugin.Tests
# нестандартный путь установки AutoCAD:
dotnet build src\PipingSpecPlugin\PipingSpecPlugin.csproj -c Release -p:AcadInstallDir="D:\Autodesk\AutoCAD 2025"
```

`build.cmd` версию не поднимает и тесты не запускает. Установщик (Inno
Setup 7, при отсутствии — 6) ставит бандл в
`%APPDATA%\Autodesk\ApplicationPlugins\PipingSpecPlugin.bundle` без прав
администратора: `PackageContents.xml`, `PipingSpecPlugin.dll`,
`DocumentFormat.OpenXml.dll`, иконки. Обновление с тем же `AppId`
перезаписывает файлы; папка не очищается.

### Квирки сборки

- `GenerateAssemblyInfo=false` — рукописный `AssemblyInfo.cs` с
  `CommandClass`/`ExtensionApplication`; версия — таргет `GenerateVersionInfo`.
- `Application` неоднозначен между `Autodesk.AutoCAD.ApplicationServices`
  и `System.Windows.Forms` — всегда алиасить (`using AcadApp = …`).
- `NoWarn=CA1416` — анализатор платформы для WinForms/WPF.
- Значения enum-атрибутов в XAML на этапе сборки не проверяются —
  ошибка всплывает только при `InitializeComponent()` внутри AutoCAD.

### Загрузка и перезагрузка

После загрузки AutoCAD **блокирует** `PipingSpecPlugin.dll` до конца
сессии. Повторный билд в ту же папку падает с `MSB3026`: закрыть AutoCAD
или собирать в другую папку (`build.cmd` пишет в `bin\Release-vX.Y.Z`).
Новая DLL подхватывается только после **перезапуска AutoCAD**;
`NETLOAD` другой копии той же сборки → `FileLoadException`.

### Диагностика прогона

- `%APPDATA%\PipingSpecPlugin\last-run.log` (предыдущий — `prev-run.log`)
  — полный трейс последней генерации: компоненты, исключённые штуцера,
  топология, изгибы (длина, масса, погонная масса, соседи), трубы по
  линиям, `DropReasons`, позиции раздела проверки. Первое место, куда
  смотреть при «деталь не попала в спецификацию» / «короткий метраж».
  Остальные команды пишут `last-run-<команда>.log`.
- MOVEBYTAG / SELECTBY* / PSAUDIT читают активный чертёж с диска; несохранённые
  изменения сохраняются только с согласия пользователя, в исходной версии
  DWG (`Database.OriginalFileVersion`), при сбое сохранения команда
  останавливается (`Commands/DrawingSaveGuard.cs`).

## 13. Сводка архитектурных решений (не пересматривать)

- **Источник истины** — модель Plant 3D через `PnP*Mgd`, чтение с диска;
  не SQLite-снимок `Piping.dcf`.
- **Функциональность** — статусы, категории, линии, исключение спутников
  арматуры и деталей оборудования, группировка по линии, контроль массы,
  раздел «Позиции, требующие проверки» вместо остановки генерации.
- **Лента** — нативно через `Autodesk.Windows.RibbonControl`, без `.cuix`.
- **Настройки** — `settings.json` в `%APPDATA%\PipingSpecPlugin`.
- **Фильтрация области dwg** — строго по `SourceDwgPath`, никогда по
  `PnPID` (rowId живут в пространстве id чертежа).
- **Аудит: изоляция одной линии** — пересечение только изоляции двух
  деталей с одинаковым заполненным номером линии не коллизия
  (`InsulationJointPolicy`), в том числе между несмежными участками;
  подтверждено пользователем 2026-10-14.
- **Аудит: соединённые детали** — пересечение деталей, соединённых через
  объект соединения (врезка, olet, шов, фланцевое соединение), не коллизия
  (`ConnectedJointPolicy`); касание без объекта соединения — коллизия.
  Решение пользователя 2026-10-14.
